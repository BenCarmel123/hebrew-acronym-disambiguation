\subsection{The task-trained encoder}
\label{sec:res-encoder}
The fine-tuned encoder reaches 273/381 (71.7\%) in candidate selection, compared with 223/381 (58.5\%) for Qwen 7B and 266/381 (69.8\%) for Qwen 14B. The latter gap is seven items (1.8 percentage points); without repeated runs or an uncertainty estimate it does not establish a stable advantage. The four API models score 317--357/381 (83.2--93.7\%), above the encoder by 11.5--22.0 points. A small task-adapted Hebrew encoder is therefore a competitive option relative to these local Qwen configurations, but does not match the tested API models at selection.

The pretrained similarity baseline scores 245/381 (64.3\%), versus 273/381 for the ranker, a difference of 28 items (7.3 points). This is not an ablation of training: separate context/candidate vectors and cosine similarity are replaced by joint encoding and a learned scoring head. The results do not establish that fine-tuning matters more than size or that Hebrew pretraining caused an advantage. Likewise, the Qwen 7B and 14B runs compare two model configurations, not a controlled intervention on size.

\subsection{Generation versus selection}
\label{sec:res-formats}
Selection scores exceed generation scores for every LLM in the main comparison. Qwen 7B rises from 31/381 (8.1\%) to 223/381 (58.5\%), and Qwen 14B from 44/381 (11.5\%) to 266/381 (69.8\%). The corresponding percentages are 54.3 to 93.7 for Gemini, 33.9 to 83.2 for GPT-4.1 mini, 43.3 to 89.0 for Claude Haiku and 48.3 to 92.1 for Grok (Figure~\ref{fig:generate-vs-select}).

Because selection is constrained to the inventory, this comparison depends on the inventory containing the reference, which holds for every test item (the oracle is 100\%). Generation must produce an expansion without that help and is checked by string inclusion, whereas selection must return a valid label. The observed gap describes these task and measurement configurations together. It does not measure the gain from candidates alone or a difference in semantic understanding under a common metric.

\subsection{DictaLM and measurement}
\label{sec:res-measurement}
The separate DictaLM results show why the scoring distinction matters (Table~\ref{tab:dictalm-supplement}). Automatic generation accepts 125 responses and Ben accepts 193. They agree on 121 accepted responses; 72 are accepted only by Ben, four only automatically and 184 by neither. Thus the annotation identifies disagreement with the string rule in both directions, without establishing a uniform semantic metric for the other models.

All 381 selection responses fail strict label-only decoding. Reading a leading label yields 243 reference matches, but this is a diagnostic of saved responses, not a replacement result. The template mismatch described in Section~\ref{sec:eval} further limits comparison; we cannot attribute the behavior to that mismatch or to Hebrew specialization.

\subsection{Conclusions}
\label{sec:conclusions}
We draw two conclusions. First, the task-trained encoder is competitive with the tested local Qwen models on candidate selection, while the API models score higher. The comparison supports this practical observation without isolating training, architecture or model size. Second, selection scores exceed generation scores for the six main LLMs under the evaluated configurations. Candidate access and scoring differ together, so this is not an isolated measure of model ability. The DictaLM annotation and decoding diagnostics illustrate why these measurements must be interpreted separately.
