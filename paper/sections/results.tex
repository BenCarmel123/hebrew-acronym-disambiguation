\subsection{The task-trained encoder}
\label{sec:res-encoder}
The task-trained encoder's 71.7\% candidate-selection score is above the two tested local Qwen configurations and below the four API systems (Table~\ref{tab:test-results}). This makes it a competitive local option under these conditions. The gap from Qwen 14B is seven items (1.8 percentage points); without repeated runs or an uncertainty estimate it does not establish a stable advantage.

The pretrained similarity baseline scores 245/381 (64.3\%), versus 273/381 for the ranker, a difference of 28 items (7.3 points). This is not an ablation of training: separate context/candidate vectors and cosine similarity are replaced by joint encoding and a learned scoring head. The results do not establish that fine-tuning matters more than size or that Hebrew pretraining caused an advantage. Likewise, the Qwen 7B and 14B runs compare two model configurations, not a controlled intervention on size.

Candidate ranking is useful when an expansion inventory is available. Like AcroBERT \citep{chen2023gladis}, the ranker scores context--candidate pairs rather than learning a separate output class for every acronym sense. It can therefore score candidates for forms absent from the documented task-training file. Latency and memory were not measured, and the ranker evaluates each candidate separately.

\subsection{Generation versus selection}
\label{sec:res-formats}
Selection scores exceed generation scores for each of the six LLMs under the task-specific rules (Figure~\ref{fig:generate-vs-select}b).

The inventory contains the reference for every test item (the oracle is 100\%). Generation receives no candidates and is checked by string inclusion; LLM selection receives candidates and must return a valid label. The gap therefore does not isolate the gain from candidates or semantic correctness under a common metric.

The saved review documents 338 automatically rejected generation responses labeled \texttt{fits} across the six systems; the breakdown is in the accompanying analysis notebook (Section~\ref{sec:artifacts}). For example, for \heb{י״ח} in item \texttt{kn4-0499}, Grok generated \heb{שמונה עשר (18)} (eighteen), while the reference is \heb{שמונה עשרה (גימטריה)} (eighteen, gematria); the string rule rejects it, but its stored label is \texttt{fits}. These are responses, not unique items or a representative sample: they illustrate disagreement with the string rule but do not quantify how much of the generation--selection gap it explains (coverage in Section~\ref{sec:eval}).

Selection returns an explicit inventory entry, while generation can express valid answers outside the list or in a different form. This practical distinction does not establish semantic superiority. In word-sense disambiguation, \citet{meconi2025large} also find strong free-form explanations under expert evaluation. In clinical abbreviation expansion, \citet{agrawal2022large} map generated text back to candidates before scoring. Their scores are not directly comparable to ours; comparing answer correctness requires a common semantic evaluation.

\subsection{DictaLM and measurement}
\label{sec:res-measurement}
The separate DictaLM results show why the scoring distinction matters (Table~\ref{tab:dictalm-supplement}). Automatic generation accepts 125 responses and author annotation (B.C.) accepts 193. They agree on 121 accepted responses; 72 are accepted only by the author, four only automatically and 184 by neither. Thus the annotation identifies disagreement with the string rule in both directions, without establishing a uniform semantic metric for the other models.

All 381 selection responses fail strict label-only decoding. Reading a leading label yields 243 reference matches, but this is a diagnostic of saved responses, not a replacement result. The template mismatch described in Section~\ref{sec:eval} further limits comparison; we cannot attribute the behavior to that mismatch or to Hebrew specialization.

\subsection{Conclusions}
\label{sec:conclusions}
We draw two conclusions. First, a small task-trained Hebrew encoder is competitive with the tested local Qwen configurations at candidate selection, while the API models score higher. Candidate ranking is thus a practical option to investigate when local inference and a known inventory are desired, although the present comparison does not isolate the contribution of training or size. Second, selection scores exceed generation scores for the six main LLMs under the evaluated configurations. This supports making candidate access an explicit design choice, while keeping the different metrics in view. Together, the findings place the choice of model alongside the choice of answer space: resolving an acronym from known alternatives and producing its expansion freely call for different system designs and different evidence of success.
