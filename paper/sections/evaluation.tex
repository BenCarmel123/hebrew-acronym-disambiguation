\section{Evaluation}
\label{sec:eval}
\subsection{Roles of the data splits}
Training supplies supervised candidate pairs. Development supports checkpoint selection in the Colab procedure and subsequent diagnostics of inputs, services and scoring; its reported accuracy is not an independent final evaluation. The separate test run is being conducted by Ben in Colab according to the authors' handoff. Completion, population identity and executed settings have not yet been verified for this draft. No test outcome or protocol is inferred from the dev configuration.

\subsection{Implemented development selection measures}
The current evaluator scores DictaBERT, Qwen selection and Gemini selection over the same requested item IDs. A completed LLM response is valid only if it is one uppercase letter within the displayed range after surrounding whitespace is removed. Text such as ``A.'' fails this parser even if its intended answer appears clear. The letter is mapped through the saved displayed order. For all three systems, correctness then requires exact equality between the selected candidate and the reference after trimming; no semantic aliases or quotation normalization are introduced at scoring time.

Let $c_i$ be one for a correct selection and zero otherwise, $N$ the number of requested occurrences and $I_a$ the occurrences of type $a$, and $A$ the observed types. The implemented summaries are
\begin{align}
\mathrm{Micro}&=\frac{1}{N}\sum_{i=1}^{N}c_i,\\
\mathrm{Macro}&=\frac{1}{|A|}\sum_{a\in A}\frac{1}{|I_a|}\sum_{i\in I_a}c_i.
\end{align}
Micro weights occurrences equally, whereas macro gives each observed type equal weight. Both are useful with the uneven development distribution. Missing reference labels make accuracy unavailable; missing type metadata makes macro unavailable. An unavailable value is not zero.

For an attempted selection arm, errors, incomplete responses, parsing failures and unrun occurrences remain in the requested denominator and are not correct. An entirely unrun arm is unmeasured. A partially executed arm can therefore have a preliminary score, but it must be identified as partial and reported with attempted and valid counts. A service failure yields no completed usable answer; a format failure is a completed answer rejected by the parser; a wrong selection is a valid candidate that mismatches the stored label. An unattempted item is a fourth, distinct status. These counts must accompany scores, since a label mismatch need not be a semantic error when the reference is defective. Comparisons restricted to valid answers would answer a different question and cannot replace this denominator.

\subsection{Free responses and paired analysis}
Generation outputs are saved for inspection and are not automatically scored by the current study. A final human judgment protocol has not yet been adopted. Exact string equality would reject some linguistically equivalent phrasings; inventory membership alone would accept a wrong candidate for the context and reject a potentially valid missing expansion. The protocol must therefore specify which variations preserve the intended expansion, how attached prefixes and named uses are handled, and how ambiguity and disagreement are resolved. The local development label decisions do not settle these general rules.

After that protocol is fixed and judgments are available, the central analysis will pair generation and selection by occurrence within each LLM. A paired table can separate items both answer correctly, items correct only in selection, items correct only in generation and items neither answers correctly. Both tasks must use the same identified population and judgment convention; missing responses must remain visible rather than silently restricting comparison to successful requests. The discussion should inspect representative errors, including valid alternatives absent from the inventory, incorrect offered candidates and answers that identify an entity without expanding its name. These are analysis questions, not categories already annotated.

Whether to add a baseline, uncertainty estimates or repeated runs remains an author decision. Repeated occurrences share types and documents, so treating all observations as independent can overstate precision. No confidence interval, significance test or repeated-seed finding is claimed here. The present exporter accepts an explicitly selected \texttt{full\_dev} artifact and leaves unjudged generation unavailable. It does not support final-test export or establish a final evaluation protocol.
