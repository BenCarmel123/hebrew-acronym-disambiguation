\section{Evaluation}
\label{sec:eval}
\subsection{Scoring}
All scores use the same 381 test items, and failures count as wrong. In selection, the chosen candidate must equal the reference expansion. An LLM must answer with exactly one in-range uppercase label (A--Z, then AA, AB, and so on; two items have 30 candidates); a response such as ``A.'' or a label followed by candidate text is invalid.

In generation, an answer is correct when the reference expansion appears in it as a substring after normalizing quotation marks. This rule can accept a longer answer that contains the reference and reject a valid variant, such as \heb{שקלים חדשים} for \heb{שקל חדש}. Generation thus measures string agreement with the reference, and selection measures exact choice of the reference; the two rules differ. For either rule we report
\begin{equation}
\mathrm{Score}=\frac{1}{N}\sum_{i=1}^{N}c_i,
\end{equation}
where $c_i=1$ when the response passes the rule and $N=381$. Technical failures and truncated responses score zero; Qwen 14B, for example, has 10 failed generation responses (2.6\%).

\subsection{Human review}
A single annotator (S.S.) reviewed 741 of the 4,953 responses of the six main LLMs and the trained encoder, focusing mostly on generated answers that the automatic rule rejected. An answer \texttt{fits} when it agrees in meaning with the displayed reference. The annotator saw which system produced each answer, but had not seen AI evaluations of the answers. Nine judgments on four items, where the reference itself may be wrong, remain unresolved. Because coverage is selective, we use this review to find disagreements with the automatic rules, not to estimate accuracy.

\subsection{DictaLM 2.0}
B.C. judged all 381 DictaLM generated answers against the reference, accepting those with the same meaning, such as a plural variant. In selection, DictaLM always adds text after the label, so we also report a lenient reading of its leading label. Its saved chat template omits a newline that the publisher specifies after \texttt{[/INST]} in the \href{https://huggingface.co/dicta-il/dictalm2.0-instruct-GGUF\#instruction-format}{GGUF instruction format}, with unknown effect. For these reasons we report DictaLM in a separate table (Table~\ref{tab:dictalm-supplement}).

\subsection{Reference points and variability}
We report four reference points: random choice among the candidates; the candidate with the most Wikipedia hits (most frequent); the candidate that yielded the most mined sentences (most mined); and an oracle that is right whenever the reference is among the candidates. Most mined (48.0\%) is optimistic, because its counts include sentences mined for the test set. Candidate order is shuffled with seed 42 and kept fixed per item. Each system ran once, with one prompt per task and one candidate order, so we report no variability estimates; option order can affect LLM choices \citep{zheng2024selection}. Items from the same type or document are not independent, so small differences should not be over-read.
