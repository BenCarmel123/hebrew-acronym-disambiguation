\section{Evaluation}
\label{sec:eval}
\subsection{Scoring}
All scores use the same 381 test items, and failures count as wrong. In selection, the chosen candidate must equal the reference expansion. Labels run A--Z, then AA, AB, and so on; two items have 30 candidates. We read the leading label of an LLM's answer, so ``A.'' or ``A.'' followed by the candidate counts as A. An answer that does not begin with a valid label is invalid. This reading changes only DictaLM's score: it always writes the candidate after the label, and would score 0\% if a bare label were required.

In generation, an answer is correct when the reference expansion appears in it as a substring after normalizing quotation marks. This rule can accept a longer answer that contains the reference and reject a valid variant, such as \heb{שקלים חדשים} for \heb{שקל חדש}. Generation thus measures string agreement with the reference, and selection measures exact choice of the reference; the two rules differ. For either rule we report
\begin{equation}
\mathrm{Score}=\frac{1}{N}\sum_{i=1}^{N}c_i,
\end{equation}
where $c_i=1$ when the response passes the rule and $N=381$. Technical failures and truncated responses score zero; Qwen 14B, for example, has 10 failed generation responses (2.6\%).

\subsection{Human review}
A single annotator (S.S.) reviewed 741 of the 4,953 responses of the six LLMs other than DictaLM and the trained encoder, focusing mostly on generated answers that the automatic rule rejected. An answer \texttt{fits} when it agrees in meaning with the displayed reference. The annotator saw which system produced each answer, but had not seen AI evaluations of the answers. Nine judgments on four items, where the reference itself may be wrong, remain unresolved. Because coverage is selective, we use this review to find disagreements with the automatic rules, not to estimate accuracy.

\subsection{DictaLM 2.0}
B.C. also judged all 381 DictaLM generated answers by hand, accepting those with the same meaning as the reference, such as a plural variant; we report this next to the automatic score (Section~\ref{sec:res-measurement}). DictaLM's saved chat template omits a newline that the publisher specifies after \texttt{[/INST]} in the \href{https://huggingface.co/dicta-il/dictalm2.0-instruct-GGUF\#instruction-format}{GGUF instruction format}, with unknown effect.

\subsection{Reference points and variability}
We report four reference points: random choice among the candidates; the candidate with the most Wikipedia hits (most frequent); the candidate that yielded the most mined sentences (most mined); and an oracle that is right whenever the reference is among the candidates. Most mined (48.0\%) is optimistic, because its counts include sentences mined for the test set. Candidate order is shuffled with seed 42 and kept fixed per item. Each system ran once, with one prompt per task and one candidate order, so we report no variability estimates; option order can affect LLM choices \citep{zheng2024selection}. Items from the same type or document are not independent, so small differences should not be over-read.
