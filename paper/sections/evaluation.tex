\section{Evaluation}
\label{sec:eval}
\subsection{Scoring}
All reported test scores retain the same 381 items, including failures. For candidate selection, the chosen candidate must equal the reference expansion. An LLM response must contain exactly one in-range uppercase label after trimming boundary whitespace. Labels are A--Z, AA, AB, and so on; two items have 30 candidates. A response such as ``A.'' or a label followed by candidate text is invalid under this strict rule.

For generation, the automatic rule checks whether the reference expansion occurs as a substring after quote normalization, with boundary whitespace stripped from the reference. It can accept a longer answer containing the reference and reject a valid variant, such as \heb{שקלים חדשים} for \heb{שקל חדש}. Thus generation measures reference-string inclusion, whereas selection measures strict label decoding followed by candidate equality. The two percentages are not the same measure of semantic correctness. For either rule we report
\begin{equation}
\mathrm{Score}=\frac{1}{N}\sum_{i=1}^{N}c_i,
\end{equation}
where $c_i=1$ when the response passes the relevant rule and $N=381$. Technical failures, including truncated responses, score zero.

Technical completion, stored format validity and automatic matching are separate fields. For generation, the stored validity flag means that \emph{any} candidate occurs in the response under normalization; it is not a general test of well-formed output. For example, Qwen 14B has 10/381 technical failures (2.6\%; nine incomplete responses and one service error), 47 format-valid responses and 44 reference matches. All use the full denominator.

\subsection{Human review and the DictaLM diagnostic}
The closed human-review export covers 741 of 4,953 responses from the six main LLMs and the trained encoder, grouped into 638 review cases. Coverage is selective: 674 of 2,050 automatic negatives and 67 of 2,886 automatic positives were reviewed; technical failures form a separate category. Of the reviewed negatives, 338 generated responses were judged to fit the context. Nine reviewed positives across four items were judged not to fit, with human clarification still pending. Later agent assessments are a separate layer and add no human decisions. This review does not estimate population accuracy or support a human ranking of systems; automatic scores remain unchanged.

Ben's DictaLM annotations are a separate, complete layer for its 381 generated responses. The source CSV records yes/no acceptance in a field named \texttt{same\_as\_gold}. It contains 193 yes labels, but no detailed rubric, per-item rationale, annotation timestamps or documented blinding. We report this acceptance rate without reconstructing a richer rule or applying it to other models.

DictaLM selection is also reported with a diagnostic parser that reads a leading label from an otherwise invalid response. This does not replace strict scoring. In addition, its saved chat template lacks the newline after \texttt{[/INST]} specified by the publisher's \href{https://huggingface.co/dicta-il/dictalm2.0-instruct-GGUF\#instruction-format}{GGUF instruction format}. The tokenized request was not logged and the effect of this mismatch is unknown. We therefore present all four DictaLM measurements in a separate supplementary table, without a common ranking.

\subsection{Reference points and variability}
We report four reference points: random choice among the candidates; the candidate with the most Wikipedia hits (most frequent); the candidate that yielded the most mined sentences (most mined); and an oracle that is right whenever the reference is among the candidates. Candidate order is shuffled with seed 42 and preserved per item. Each system has one reported run, without repeated-seed or decoding-variability estimates, so small differences should not be over-read. Items from the same type or document are not independent. The identified exports retain per-response rules and run IDs; the main notebook documents the saved-result analysis without requiring model execution.
