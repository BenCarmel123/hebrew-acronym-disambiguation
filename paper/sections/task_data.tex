\section{Task and Data}
\label{sec:data}
\subsection{The unit of prediction}
Each item contains a sentence $x$, an acronym $a$, a candidate inventory $C$ and a reference answer $y\in C$. For the encoder, a character span $s$ identifies the target text $x[s]$, marked with \texttt{[ACR]} and \texttt{[/ACR]}. In saved test inference this span is derived automatically; LLM prompts name the acronym alongside the original sentence (Section~\ref{sec:systems}).

Generation predicts an answer from sentence context and target information, without candidates. Selection picks one member of $C$ for the same item. We use \emph{expansion} as shorthand for the stored inventory answer: besides ordinary spelled-out expressions, it includes numerical interpretations in gematria (the use of Hebrew letters as numbers) and conventional or named uses that are not literal expansions. For example, the reference for \heb{ח״י} in one test sentence is \heb{שמונה עשרה בגימטריה} (eighteen in gematria; Table~\ref{tab:res-examples}). Evaluation therefore measures agreement with this inventory and its reference labels, not only recovery of the words that formed an acronym. We retain all such items and labels.

The output spaces are:
\begin{equation}
\begin{aligned}
\hat{y}^{\mathrm{gen}}&=f(x,t)\in\Sigma^{*},\\
\hat{y}^{\mathrm{sel}}&=\operatorname*{arg\,max}_{c\in C}\mathrm{score}(x,t,c),
\end{aligned}
\end{equation}
where $t$ denotes the target information and $\Sigma^{*}$ is the set of text strings, so generation may return any string, while selection returns one candidate in $C$.

\subsection{Sources and construction}
The inventory contains 2,702 candidate rows for 638 acronym types: merged Hebrew Wikipedia/Wiktionary entries, 636 gematria entries and 64 human-review additions. Additions arose during Knesset review, including test-related review; the inventory is therefore not an independently complete untouched dictionary. Sentences come from Hebrew Wikipedia and the Knesset plenary corpus (HaifaCLGroup/KnessetCorpus). Mining filters targeted 40--200 characters, clear acronym boundaries (allowing attached prefixes), and no definitions or additional acronyms. These were preparation intentions, not universal properties of retained or authored items: for example, \texttt{kn4-0299} retains an explicit definition. Candidate sources and contextual labels remain distinct.

Sentences are of four kinds. \emph{Natural} sentences contain the acronym as written. \emph{Substituted} sentences come from Wikipedia: a spelled-out expansion was replaced with the acronym, and the removed expression is a weak label. \emph{Deglossed} sentences are natural sentences with an adjacent explanation removed. \emph{Claude-authored} sentences were written by an LLM to add senses to types that had few. Substituted and authored sentences give labels cheaply, but they need not read like naturally abbreviated text.

\paragraph{Train.} The current encoder training file contains 2,829 items, which give 12,684 sentence--candidate pairs. Its exact identity at historical training time is not recovered. Most items are substituted, so most labels are weak. Retained preparation reproduces 2,665 training and 62 development rows; the extra 164 stored training rows comprise 136 authored examples and 28 truncated contexts. The historical dataset card reports 142 authored training rows for an earlier file. Stored labels were reused without comprehensive reannotation.

\paragraph{Development.} The research development set holds 62 natural Knesset items for 11 types and supports encoder checkpoint selection and development comparisons. It is distinct from both the execution pilot and test cohort. Its labels combine reused human reviews and AI-assisted author decisions, rather than independent annotation. Each type has only one observed reference sense, so this set does not establish within-type discrimination.

\paragraph{Test.} The test set has 381 items for 60 types. Human-review evidence is documented for all 253 Knesset items; the 87 Claude-authored items carry a human-review provenance marker. The 41 Wikipedia items have a stored verified status but no recorded review verdict, so the available records do not establish human review of every test label. Knesset review records categorize 221 labels as confirmed and 32 as corrected; the latter's original labels are not recoverable, so these are recorded actions, not verified before/after corrections or proof of correctness. The 87 authored items add three sentences each for 29 types, only 28 of which have retained Knesset test examples. Removing 14 Knesset items from four protocols yielded the retained cohort. Gemini collected these 381 items directly; other saved runs may contain 395 responses with scoring restricted to the retained 381. No inter-annotator agreement estimate is available. This label provenance is distinct from the review of model responses in Section~\ref{sec:eval}.

\subsection{Separation of the sets}
\label{sec:separation}
Preparation checks establish structural validity, not label correctness. Exact acronym and sentence strings are disjoint across the documented encoder train/dev/test files. Their non-empty document keys are disjoint between test and train/dev, while train and dev share three keys. In contrast, the historical source \path{data/splits/train_items.csv} overlaps 60 protocols with 97 test items; the historical checkpoint's actual inputs remain unknown. Final-letter variants \heb{אג״ם}/\heb{אג״מ} and \heb{מל״ם}/\heb{מל״מ} cross the exact-string split in seven test items; prefixed forms can cross it too. Thus the split establishes neither unseen acronym families nor absence from pretraining.
