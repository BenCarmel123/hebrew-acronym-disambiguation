\section{Task and Data}
\label{sec:data}
\subsection{The unit of prediction}
Each item contains a sentence $x$, an acronym $a$, a candidate inventory $C$ and a reference answer $y\in C$. For the encoder, the target is marked in the sentence with \texttt{[ACR]} and \texttt{[/ACR]}. LLM prompts name the acronym alongside the original sentence (Section~\ref{sec:systems}).

Generation predicts an answer from sentence context and target information, without candidates. Selection picks one member of $C$ for the same item. We use \emph{expansion} as shorthand for the stored inventory answer: besides ordinary spelled-out expressions, it includes numerical interpretations in gematria (the use of Hebrew letters as numbers) and conventional or named uses that are not literal expansions. For example, the reference for \heb{ח״י} in one test sentence is \heb{שמונה עשרה בגימטריה} (eighteen in gematria, Table~\ref{app:res-examples}). Evaluation therefore measures agreement with this inventory and its reference labels, not only recovery of the words that formed an acronym.

The output spaces are:
\begin{equation}
\begin{aligned}
\hat{y}^{\mathrm{gen}}&=f(x,t)\in\Sigma^{*},\\
\hat{y}^{\mathrm{sel}}&=\operatorname*{arg\,max}_{c\in C}\mathrm{score}(x,t,c),
\end{aligned}
\end{equation}
where $t$ denotes the target information and $\Sigma^{*}$ is the set of text strings, so generation may return any string, while selection returns one candidate in $C$.

\subsection{Sources and construction}
The candidate inventory lists 2,702 possible expansions for 638 acronym types. Of these, 2,002 come from Hebrew Wikipedia and Wiktionary abbreviation pages, 636 are gematria readings, and 64 were added by hand when a reviewer found a missing sense while checking Knesset sentences, some of them test sentences. The inventory is therefore not a dictionary built independently of the test set. Sentences come from Hebrew Wikipedia and from the Knesset Corpus, a collection of Israeli parliament plenary transcripts released by the University of Haifa (\texttt{HaifaCLGroup/KnessetCorpus} on Hugging Face). Mining kept sentences of 40--200 characters with a clear acronym boundary (allowing attached prefixes) and no definitions or other acronyms, although a few retained items still break these rules.

\subsection{Train, development and test sets}
Table~\ref{tab:data} gives the size of the documented files and their kinds of sentence. \emph{Natural} sentences contain the acronym as written. \emph{Substituted} sentences come from Wikipedia: a spelled-out expansion was replaced with the acronym, and the removed expression serves as a weak label. \emph{Deglossed} sentences are natural sentences with an adjacent explanation removed. \emph{Claude-authored} sentences were written by an LLM to add senses to types that had few. Substituted and authored sentences give labels cheaply, but need not read like naturally abbreviated text.

\paragraph{Train.} The documented encoder training file contains 2,829 items, which give 12,684 sentence--candidate pairs. Most labels are weak labels from substitution, reused without reannotation. Regenerating the preparation reproduces 2,665 of these rows, while the remaining 164 consist of 136 authored examples and 28 truncated contexts.

\paragraph{Development.} The documented development set holds 62 natural Knesset items for 11 types, each with a single observed sense. Its labels combine reused human reviews and AI-assisted author decisions. The training code selects by development loss, but the selected historical epoch is unrecorded.

\paragraph{Test.} The test set has 381 items for 60 acronym types: 253 Knesset, 41 Wikipedia and 87 Claude-authored sentences. Their labels have different review records: a human reviewed all 253 Knesset labels, confirming 221 and correcting 32, but the original labels of the corrected items were not kept. The 87 authored items, three sentences for each of 29 types, are marked as human-reviewed. By contrast, the 41 Wikipedia items are marked as verified, but no review verdict was recorded. One person reviewed the labels, so no inter-annotator agreement is available. We removed 14 Knesset items from four protocols that also supply training items, leaving 381 of the original 395. All scores use these 381, although some saved runs also hold responses for the removed items. This label review is separate from the review of model responses in Section~\ref{sec:eval}.

\subsection{Separation of the sets}
\label{sec:separation}
We split by acronym type, with exact acronym and sentence strings disjoint across the train, development and test files. At the document level, the test set shares no document with train or development, although those two sets share three documents. Near-identical acronym forms can nevertheless cross the split: the final-letter variants \heb{אג״ם}/\heb{אג״מ} and \heb{מל״ם}/\heb{מל״מ} affect seven test items, and prefixed forms can cross it too. The split therefore tests unseen acronym strings, not unseen acronym families.
